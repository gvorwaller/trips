# 2026-07-03

## Duplicate day-plan stops (td-9f9807)

Fixed the duplicate route-stop path behind stale trip notes and Google Maps route-generation failures.
Day plans now reject duplicate stops by physical location rather than title: same itinerary item, same
Google `place_id`, or coordinates within 30 meters. The same validation also checks route anchors, so
an anchor cannot duplicate a saved stop.

Added clear action failures for duplicate adds from the saved-plan picker, day-plan builder, and
suggested-stop buttons. Existing bad data is also guarded at route-calculation time: duplicate
coordinates now fail before calling Google Directions, with a message to remove duplicate stops.

Verification:
- `npm test` — 87 passing
- `npm run test:db` — 32 passing

Follow-up: the duplicate-stop guard was working, but the saved-plan Add stop form routed its
failure message into the route-status area, which was easy to miss. Added a dedicated per-plan
Add stop error alert directly under the picker and included `plan_id` in duplicate add-stop
failures so the warning also renders on full form-post fallback.

Follow-up verification:
- `npm run check` — 0 errors/warnings
- `npm run build` — passed
- Browser QA on `npm run dev:test`: selecting an already-saved stop kept the stop count at 1 and
  rendered “QA Downeast Scenic Railroad is already in this route.” under the Add stop controls.
