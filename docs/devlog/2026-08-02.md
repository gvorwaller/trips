## C — plan cards collapsed by default (td-1372a5), two QA rounds

Commit `44f8284` + a follow-up fix commit. Feature: day plans start collapsed
(tri-state `collapse-state.ts` map, legacy bare-array upgrade preserved);
folded cards show title/date/weather/actions/progress/driving summary.

**Round 1 findings (CODEX):** Safari print dropped the Expenses section from
the PDF; day-plan card titles rendered one letter per line when the actions row
was wide; keyboard Enter/Space reported dead on the new toggle.

**Round 2, after the first fix, the real print root cause emerged.** The
original `printing`-flag design (raise flag, lower on `afterprint`) had a
genuine race — Safari fires `afterprint` before its lazy pagination finishes —
so the mechanism was replaced outright: folded content now **stays in the DOM**
hidden by a `.folded` class, and `@media print` reveals it with
`display: revert`. `printSheet()` is just `window.print()`; nothing to race.
But Expenses *still* vanished, and CODEX observed it vanished even when
expanded on screen — which the afterprint theory could not explain. Actual
cause: `src/app.css` print CSS set `.card { break-inside: avoid }`, and
**Safari drops an unbreakable block taller than one page from the PDF entirely
instead of paginating it**. With everything print-expanded, section cards
routinely exceed a page, and the last tall card (Expenses) was the consistent
casualty. Fix: `.card` and `.dayplan-card` are `break-inside: auto` in print;
row-level `li` atomicity retained; `.dayplan-head` kept atomic. Final gate:
complete 15-page PDF, Expenses present, no row straddles a page, fold state
untouched by printing (now true by construction).

The keyboard finding was **withdrawn** after retesting with trusted input —
native `<button>`, no key handlers on the page; the failure was synthetic
`locator.press()` events not triggering default button activation.

The title squeeze: `.dayplan-head` is flex with a basis-0 `min-width: 0` title
column; a wide actions row (the too-many-stops warning from B) starved it to
~1ch. Fix: `flex-wrap` on the head + 240px title basis so actions wrap below.

**Deferred by owner's choice, recorded not forgotten:** the folded card at
390px is still ~738px tall (weather strip + up to 6 action buttons remain
visible; CODEX suggests hiding weather/warning and tucking secondary actions
behind a "More" control when folded), and the ~500ms collapsed→expanded
hydration flash on reload (true fix is server-side per-user prefs, already in
the plan's Ideas list).
