# 2026-07-28 Devlog

## 19:55 EST - Searchable place pickers + mobile overflow fixes (commit d457f15)

### Summary

Replaced the native `<select>` parent/place pickers on the trip page with the existing
`SearchableSelect` combobox so a trip with dozens of places no longer requires scrolling a
long dropdown, and fixed four separate causes of horizontal scrolling on the trip page at
phone widths. Deployed to production; `trips.gaylon.photos/api/health` reports
`{"db":"ok","version":"d457f15"}`.

### What Was Done

**Pickers converted to `SearchableSelect`**

- "Import under" (itinerary import) — the original request.
- Both day-plan place pickers: the card's "Add a place…" (`?/dayplan-add-stop`) and the
  builder's "Choose a place…". Each previously paired a **separate** `Filter places…` text
  input with a native select; the combobox does both jobs, so those inputs plus
  `dayPlanSearch` and `dayPlanPlacesFiltered` were deleted.
- "Move under" raised to `maxResults={500}` to match "Import under".

**Bugs found and fixed in `SearchableSelect` (several pre-existing)**

- *Opened pre-filtered.* When closed, the input displays the selected option's label, and
  that label was being used as the filter — so focusing the list showed only the item
  already selected. This would have defeated the entire point of adding search. Fixed with
  a `typed` flag; filter on `query` only after the user actually types. Pre-existing in
  "Move under".
- *Click on an already-focused input never opened the list.* `onfocus` does not fire again
  for an element that already has focus. Added `onpointerdown`/`onclick` alongside
  `onfocus`. Also makes click-to-reopen work after Escape.
- *Stale hidden selection.* Selecting a place then clearing the visible text left the old
  id in the hidden input with the submit button still enabled — a place the user thought
  they had removed remained submittable. `onInput` now drops the selection when the typed
  text diverges from the committed label.
- *`derived_inert` warning.* `closeList()` schedules a 120 ms blur timer whose callback
  reads the `selectedLabel` derived. Clicking "Add stop" blurs the input, the enhanced
  submit then destroys the day-plan card, and the timer fires afterwards against a
  destroyed effect. Added `onDestroy(clearCloseTimer)`.
- *Crash introduced mid-session.* `bind:selectedValue={dayPlanAddStopSel[plan.id]}` on a
  record that starts empty passes `undefined` to a `$bindable('')` prop, which **throws**
  `props_invalid_value` in both dev and prod — every day-plan card would have failed to
  render. Replaced with one-way `selectedValue` + a new optional `onSelect` callback.

**New `SearchableSelect` capabilities**

- Optional `disabled` options (greyed, unselectable, skipped by arrow keys) so the builder
  can keep showing places already added, as the old `<option disabled>` did.
- `onSelect` callback for parents whose value may be `undefined`, where `bind:` throws.
- Truncated results are now reported (`N more — keep typing to narrow`) instead of silently
  capping the list.

**Mobile horizontal overflow — four distinct layers**

Page measured 715 px wide at a 375 px viewport. Each fix exposed the next:

1. `.dayplan-list` is a single implicit `auto` grid track, whose minimum is its content's
   *min-content* width → `grid-template-columns: minmax(0, 1fr)` + `min-width: 0` on
   `.dayplan-card`. (683 → 309 px, page 715 → 702.)
2. Native `<select>`s size to their widest `<option>` and default to `min-width: auto` →
   `.add-row select`, `.dayplan-builder select`, `.route-tools select` constrained.
   (656 px select inside a 283 px row; card interior 669 → 307.)
3. The **same** implicit-grid failure one level down inside `.dayplan-builder`, only
   visible with the builder open → same grid fix plus `min-width: 0` on `.builder-step`
   (which had no CSS rule at all) and `.cand-actions`. (695 → 305.)
4. File inputs have an intrinsic width (filename + button) exceeding a phone viewport →
   component-scoped `input[type='file'] { min-width: 0; max-width: 100% }`.

Long quick-group chips now wrap rather than widening the row. Final: **375/375/375** with
the builder both open and closed. No `overflow-x: hidden` anywhere — causes fixed, not
hidden.

**Per-plan add-stop state**

The card picker was `<select required>`, which blocked empty submits. The combobox posts
through a **hidden** input, and browsers exclude hidden inputs from constraint validation,
so `required` would silently do nothing. Replaced with `dayPlanAddStopSel`, a record keyed
by plan id, gating the Add stop button and explicitly reset on success (a native form reset
cannot clear the component's internal state). Verified independent across two real plans.

### Key Technical Insight

**`npm run check` and `npm run build` passed clean through every single one of these bugs.**
Static analysis cannot see a runtime prop contract (`props_invalid_value` throws at render),
a focus event that never fires, a timer outliving its component, or a hidden input excluded
from constraint validation. Browser verification was not a formality here — it was the only
thing that caught any of it.

Specific gotchas worth remembering:

- A **single-column implicit grid** (`display: grid` with no `grid-template-columns`) sizes
  its track to min-content, so any wide descendant blows out the viewport. `minmax(0, 1fr)`
  is the fix, and `min-width: 0` on the *item* is still needed on top of it. This pattern
  recurred twice in the same file at different nesting levels.
- Replacing a `<select>` with a custom control silently drops `required`, because the value
  now posts through a hidden input. Gate the submit button on state instead.
- `bind:` to a possibly-`undefined` value on a prop declared `$bindable(<fallback>)` throws.
  Use one-way value + a callback when the parent's value can be undefined
  (`svelte/src/internal/client/errors.js` → `props_invalid_value`).
- Writing to a `$bindable` prop that the parent did **not** bind still works: Svelte falls
  back to an internal writable derived (`reactivity/props.js` ~line 391). That is what lets
  "Move under" keep using the hidden input with a one-way `selectedValue`.

## Places dates and schedule report

### Summary

Places now show their assigned date directly in the itinerary outline, without opening
Edit mode. A new **Places schedule** report provides a chronological view of dated places
and a grouped backlog of undated places for planning the remainder of an active trip.

The feature is intentionally limited to itinerary items whose type is `place`. Day plans,
reservations, sections, and notes do not appear in the report. Non-place ancestors are used
only as breadcrumb context.

### What Was Done

- Added compact date badges to dated place rows in the existing Places outline.
- Added a **Schedule** link in the Places card header.
- Added `/trips/[id]/places/schedule`, with:
  - dated places grouped by day in ascending order;
  - clear before-trip and after-trip warnings;
  - breadcrumbs, notes, map links, and directions links;
  - summary counts for dated, unscheduled, and outside-trip places;
  - a collapsed **Unscheduled places** backlog grouped by top-level branch;
  - print styling for a clean planning report.
- Added a pure schedule builder and focused tests for Places-only filtering, ordering,
  breadcrumbs, grouping, and trip-range status.
- Adjusted the Places row controls at narrow widths so titles remain readable. The primary
  mobile acceptance target is landscape orientation; laptop and phone-landscape layouts
  retain the inline control layout.

### Verification

- Browser-tested the main Places outline and the new report using seeded dated, undated,
  before-trip, and in-trip places.
- Verified non-place itinerary items are excluded.
- Verified report links return to the corresponding place row.
- Verified no horizontal overflow at 390 px portrait or 844 x 390 phone landscape.
- `npm test` — 13 files, 91 tests passed
- `npm run check`
- `npm run build`

No migration was required.
