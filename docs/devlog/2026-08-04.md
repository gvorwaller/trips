# 2026-08-04 — td-b580a8: DirectionsService is gone

Both day-plan routing helpers migrated off the deprecated browser
DirectionsService onto the server-side Routes API v2 (computeRoutes),
following route-matrix.ts conventions: server-held GOOGLE_GEOCODING_KEY,
TRAFFIC_UNAWARE determinism → api_cache (7-day TTL, hashed keys per 0012),
typed statuses. New `src/lib/server/route-directions.ts` +
`/api/route/directions`; `src/lib/route.ts` is now a thin client keeping fast
local pre-checks. Nothing in the browser loads the routes JS library anymore.
Repeat recalculations of an unchanged plan now cost zero API spend.

Four adversarial review rounds (peer CODEX), 11 findings — the pattern was
"fail closed at the wire": a leftover display-key gate on Calculate that
contradicted the migration boundary; optimize leg-count and order-omission
must reject, not reinterpret; totals accumulate raw seconds and round ONCE
(summing per-leg rounded minutes drifts by legs/2); the 25-entry cap counts
INTERMEDIATES, not stops (a real capacity regression); endpoint payloads get
strict 400s; upstream conditions travel as classified 429/502/503 so
SvelteKit can't sanitize the message away; and provided-but-invalid wire
values (non-integer distances, unparseable durations, string/fractional
optimize indices) are 'malformed' 502s rejected BEFORE cache admission —
never laundered into zeroes. The behavioral suite from branch A was ported
onto the real wire shapes, plus a RequestHandler-boundary suite, because the
contract that matters is what the HTTP client receives.

Browser QA: full pass — parity to the decimal with the old engine on both
plans, the no-display-key path routes correctly, the coordinates-missing 400
verified live at the endpoint (UI can't reach it: Calculate disables for
unlocated stops — noted as testability nuance, not defect), straight-line
fallback verified by emptying the server key on an isolated instance.

Relay archaeology, for the wake-on-message doc: CODEX's message timestamps
trail wall clock (~1 h), so timestamp-filtered relay_wait quietly skips its
messages; and a leaked relay_wait slot starves every waiter in the MCP
process. The reliable waiter is the relay's own watch CLI as a background OS
process (scripts/relay-watch.js) + history polling — used for this round's
QA wait and it worked first try.
