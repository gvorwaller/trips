# 2026-08-03 — Branch D: place check-off, and the lock-order excavation

td-430ffe, branch `feat/place-visited`. Owner-mandated gate: peer CODEX ran an
adversarial code review BEFORE browser QA, stopping on any substantive finding.
It took **six review rounds** and surfaced **seven confirmed P1s** — three of
them latent in *pre-existing* production code — before a clean pass and a full
browser matrix. This file records the mechanism chain because the final shape
looks obvious and wasn't.

## The feature

Places are checkable as visited from the Places tree (and the place page), with
the itinerary item as the single source of truth. Any check-off — tree, place
page, or any day-plan stop copy — fans out transactionally to the item and
every linked stop copy, both directions. Orphan stops (place deleted) keep an
independent flag. Viewer accounts may use all three check-off paths
(`isViewerAllowedMutation` gained `/api/itinerary/visited`; cs.md updated in
lockstep). Places header shows an "X / Y visited" roll-up. Migrations:

- **0014** — `itinerary_items.visited` + bool_or reconciliation of existing
  stop copies (any visited copy promotes its item, then copies normalise).
  Carries a deploy-precondition query: zero cross-trip stop links required.
- **0015** — partial index on `day_plan_stops(itinerary_item_id)`.
- **0016** — trigger making cross-trip stop links impossible at the data layer.

## What the review rounds caught, in order

1. **Invariant decay on future writes.** The migration reconciled existing
   rows, but `insertStop` and `duplicateDayPlan` created copies with default
   FALSE — a visited place added to a new plan was born disagreeing. Copies
   are now born from the item's flag (duplicates: linked copies mirror the
   item; orphan copies deliberately reset).
2. **Viewer scope hole.** `setItemVisited` never required
   `item_type='place'`, so the viewer-whitelisted endpoint could flip
   sections/days/notes. Authorization now includes the type predicate.
3. **Deadlock #1.** The two visited writers took locks in opposite orders
   (item→stops vs stop→item→stops).
4. **Indirect non-place bypass.** A stop linked to a non-place item would let
   the older stop endpoint mutate that item. `insertStop` is now place-only
   (all 115 prod linked stops are places) and the stop-side item update
   independently re-asserts owner + place.
5. **Deadlock #2 — the 0010 triggers.** Every `day_plans`/`day_plan_stops`/
   `itinerary_items` write also locks the **trips row** via the activity-touch
   triggers, so lock analysis that ignores them is wrong. My own race test
   caught this version; CODEX's round-4 repro then showed the whole class:
   every multi-stop writer (addStop→clearDriving, removeStop, reorderStops,
   bulk driving/ai-notes, optimize, deleteDayPlan — which was a bare
   non-transactional DELETE) fired a trigger before holding all stop locks.
6. **Deadlock #3 — the plan row.** `updateDayPlan` naturally locks
   plan→trips; stop-sweeping writers went stops→trips→plan. Reproduced.
7. **Insert phantoms.** Row locks don't lock membership: on an empty plan the
   stop prelock locked nothing, and `addStop` computed `MAX(sort_order)+1`
   before any lock — two concurrent adds committed duplicate sort_order.

**The resulting rule, now in `lockPlanStops`'s contract comment:** canonical
lock order is **item(s) → plan row → stop rows → trips**, all row locks taken
with trigger-free `SELECT … FOR UPDATE` before any trigger-firing write. The
plan-row lock does double duty: it is the ordering edge against
`updateDayPlan`, and — because a child INSERT needs an FK key-share on its
parent — it is the membership barrier that makes stop enumeration and MAX
computation phantom-proof. Deterministic held-lock dbtests (not Promise.all
schedule luck) pin each reproduced schedule; the dbtest suite was run five
times consecutively per round to shake flakiness.

**Declared boundary:** `deleteItem`/`deleteTrip` cascade paths retain
trips-first edges (pre-existing, destructive-op, retryable) — td-36b55b, with
CODEX's explicit agreement.

alert when the PATCH fails, and drop re-clicks mid-flight — a native checkbox
flips its own DOM before the request, so a failed save previously lied.

# Branch E: birds trip picker + place dates (td-428a1d, td-2092b7)

Six adversarial review rounds by peer CODEX plus a full browser matrix; final
signoff "no open findings". Roughly 18 findings fixed, every one in territory
the automated suites cannot reach (client concurrency, UI state machines, one
source-encoding defect). The notable ones:

- **A pre-existing silent import cap.** `importItineraryCandidates` sliced to
  200 items and reported success; the birds flow could offer 5,000. Now an
  explicit `ImportTooLargeError` rejection counting nested children, with the
  limit constant shared (`src/lib/import-limits.ts`) so UI and server state
  the same number.
- **The Svelte batched-flush transport bug.** A scoped trip id passed through
  a reactive hidden-input attribute misses a synchronous `requestSubmit()`'s
  FormData. Transport is now an imperative DOM `.value` write.
- **A whole taxonomy of candidate-panel races**, closed by two tokens: a
  monotonic Birds request generation (stale completions drop themselves; a
  reset BUMPS it, cancelling in-flight work) and a shared panel-ownership
  generation claimed by every producer, with claim+clear atomic at submit.
  Import captures its generation and never steals a newer panel.
- **Username as a context boundary**: editing it wipes all Birds-derived
  state (and a Birds-owned panel), cache keys are username-composite, and any
  successful import invalidates the cache (duplicate annotations are stale by
  definition).
- **The bind-before-onchange dead end** (browser QA catch): a select's bound
  value commits before `onchange` fires, so "re-select the trip" recovery
  instructions were no-ops. `birdsCommittedTrip` tracks the actually-displayed
  trip and every non-displaying completion reverts the dropdown to it.
- **A literal NUL byte** briefly made `+page.svelte` read as binary to every
  text tool. Composite keys are now `JSON.stringify` pairs.

Truncation is a correctness boundary, not a warning: discovery fetches the
5000 cap; if still truncated, All-trips import is blocked, per-trip scoped
refetches guarantee completeness, counts render as lower bounds ("10+") until
corrected, and a manual trip-id input reaches trips the truncated discovery
never listed. `BIRDS_IMPORT_FETCH_LIMIT` (test envs) lowers the cap so all of
it is browser-testable — CODEX verified the full truncated matrix against an
isolated instance, including deliberately killing birds to prove the failure
rollback, and caught the import lock empirically via a slow geocoded
candidate.

Dates (td-2092b7): add-row and paste-many forms take an optional date;
birds imports pin one only for genuine single-day trips.

Recurring lesson for future fixtures: the importer's fuzzy duplicate matcher
treats substring containment as a dupe ("Place 1" ⊂ "Place 1000") — synthetic
test titles must be fixed-width unique.
