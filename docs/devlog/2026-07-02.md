## Multi-user support (td-d3af9d) + Help revamp (td-22eaf9)

Implemented the full plan in `docs/2026-07-02-multiuser-plan.md` (written earlier today, already
Codex-reviewed), Phases 1–5. Phase 6 (prod rollout: backup → migrate → deploy → create Caleb) is
**not done** — it's gated on explicit per-step confirmation.

**Phase 1 — migration `0011_multi_user.sql`.** Roles become `admin | user | viewer` (the single
`owner` row migrates to `admin`); viewers carry `views_user_id → users(id)` naming whose trips they
read. Integrity is layered: a CHECK (`users_views_matches_role`: only-and-always viewers have the
link) plus a `BEFORE INSERT OR UPDATE` trigger for the cross-row rules a CHECK can't see — viewer
must view an admin/user (never a viewer, never itself), and an account can't be demoted to viewer
while it still owns trips/templates or is itself viewed. All seven rejection shapes verified with
raw psql against the test cluster before any app code changed. `0012_cache_key_privacy.sql` purges
old-format `place-text:*` cache rows (see Phase 4).

**Phase 2 — killed the `getOwnerId()` singleton.** The one thing that made the app single-user was
`hooks.server.ts` assigning every session the first owner's id (cached for process lifetime).
Now `locals.ownerId = user.role === 'viewer' ? user.views_user_id : user.id`, with
`validateSession()` selecting `views_user_id` so the hook needs no extra query. The ~70
`locals.ownerId` call sites in routes/lib didn't change at all — the payoff of the existing
owner-scoped design. Role unions updated in `app.d.ts`/`auth.ts`/`session.ts`/`users.ts`; rename
sweep (`rg "owner|viewer"`) reconciled — remaining "owner" hits are the `owner_id` columns and
"the owning account" prose, which stay correct.

**Phase 3 — birds-style admin Users panel in /settings.** Everyone non-viewer gets the existing
profile/own-password sections; admins additionally get: the full account list (role badges, viewer
links, last login), `users-create` (role picker; viewer creation picks whose trips it views,
defaulting to the creating admin), and `users-set-password` (no current password — the panel copy
states plainly this is impersonation-level capability; target's sessions are destroyed, an
improvement over birds). Both flows sit behind the project's confirm-modal convention. The old
single-viewer `viewer-*` actions are retired. `scripts/create-user.mjs` stays as break-glass:
roles updated, viewers require `--views <username>`, validates the target, keeps the idempotent
upsert (also switched from `process.exit()` to `process.exitCode` per the known output-truncation
gotcha).

  in `api_cache.cache_key`. Now hashes the query portion (`sha256(...).slice(0,16)`) — plaintext
  titles stay out of the shared table while identical queries still share a row. `api_cache`

flag that was silently disabled long ago. And any test asserting on Google Places fuzzy-match
output for a junk query is a coin flip — fixtures must name a real POI at its true coordinates.
